# Dreamscapes 최종 리팩터링

기존 화면과 파라미터, 작업 순서, 파일 형식 및 QML 공개 인터페이스를 보존하면서 요청·실행·진행 전달의 책임을 구분한다. 에디터와 홈·생성·파일·갤러리·출력 경로에 적용한 기존 변경은 유지하고, 마지막 정리는 생성 실행 경계와 전체 회귀 검증에 집중한다.

## 생성 처리의 파일 구성

- `GenerationController.cpp`: 화면 상태, 저장소·모델 연결, 큐 조정, 결과 공개와 완료 처리이다.
- `GenerationRequests.cpp`: 이미지·비디오·고급 생성 요청의 검증과 파라미터 구성이다.
- `GenerationExecution.cpp`: 네이티브 실행과 외부 워커 시작·모델 준비이다.
- `GenerationProgress.cpp`: 진행 감시, 워커 프로토콜 입력, 프리뷰와 결과 전달이다.
- `NativeGenerationWork.cpp`: 값으로 받은 네이티브 작업과 프리뷰 준비이다.
- `GenerationProcess.cpp`: Core가 소유하는 프로세스·파이프와 GUI 전달의 경계이다.
- `GenerationPublication.cpp`: 결과 검증, 이미지 변환과 파일 공개이다.

컨트롤러의 기존 메서드 정의는 분리한 파일 전체에 정확히 한 번씩 남기며, 공개 헤더와 파라미터를 바꾸지 않는다. 불필요한 상속이나 기능별 대체 API를 추가하지 않는다.

## 취소와 앱 수명

취소는 내부 상태와 실행 중단 요청을 먼저 완료한 후 화면에 알린다. 알림을 받은 쪽이 컨트롤러를 제거하더라도 이후 삭제된 객체에 접근하지 않는다. 실행 대기 중 이미 취소되거나 관심이 종료된 네이티브 입력은 공급자를 호출하지 않는다.

프로세스 작업은 기존 iiSDKCore의 `Runtime`과 `EventLoop`가 소유한다. 화면을 닫을 때에는 기다리지 않고 취소 의도와 파일 수명을 넘긴다. 애플리케이션의 `aboutToQuit`에서는 새 작업 접수를 닫고 소유한 프로세스 회수와 작업자 종료를 끝낸다. 화면을 제거하는 경로와 앱 전체를 종료하는 경로에 각각 필요한 수명 경계를 적용한다.

## 보존 및 검증

기존 LVRS 패키지, 윈도우·패널 구성, 보기 옵션, 타임라인과 파일·문서 상태의 구분을 유지한다. SDK 전역 설치나 기존 사용자 데이터의 재작성은 리팩터링에 포함하지 않는다.

변경마다 빌드와 행동 검사를 수행하며 마지막에는 등록된 전체 CTest 그룹, QML 검사, 배포 후보의 리소스·모듈·서명·버전 및 단일 앱 규칙을 확인한다. 취소 전 입력, 알림 중 객체 제거, 앱 종료 시 프로세스 회수는 별도의 회귀 검사로 고정한다. 실제 외부 서비스 인증·업로드나 물리 장치·실제 모델 추론은 격리된 회귀 검사와 구분하여 보고한다.

파일 목록 검사는 비동기 새로고침의 결과가 전달된 뒤 삭제 반영을 확인한다. 갤러리 행 갱신 검사는 초기 GridView 배치를 완료한 뒤 타일 수와 기존 타일의 수명을 비교한다. 검사 중 단언이 실패하여도 패널을 부모 윈도우보다 먼저 제거한다. 파일 삭제 반영·타일 수명 조건과 작업별 제한 시간은 완화하지 않는다.

기본 CTest 구성에서는 GUI의 123개 검사 함수를 기존 세부 그룹 44개가 담당하는 117개와 별도 그룹 6개가 담당하는 6개로 배치한다. 나머지 6개는 기동·모바일 홈·고급 기본값·고급 컨트롤·생성 준비·공유 윈도우를 각각 별도 프로세스로 실행하여 Qt 전역 단축키 컨텍스트와 윈도우 수명이 다른 검사에 섞이지 않게 한다. 각 함수의 데이터 행과 단언을 그대로 실행하고, 기존 전체 GUI 실행의 중복만 줄인다. 등록된 그룹 전체를 대조하여 누락된 함수가 없음을 확인한다. 단일 프로세스에서 전체 GUI 검사를 연속 실행하려면 `build/bin/DreamscapesGuiTests`를 직접 실행할 수 있으나 이 구성의 격리 검증과 구분한다.

`Dreamscapes.GuiRegistry`는 실행 파일이 제공하는 실제 Qt 검사 함수 목록과 CTest의 등록 명령을 대조한다. 누락된 함수, 알 수 없는 선택자, 전체 GUI를 다시 실행하는 무지정 그룹을 발견하면 실패한다. 이 검사는 데이터 행을 선택하지 않은 함수 단위 등록만 인정하므로 특정 데이터 행만 실행한 것을 전체 함수 검증으로 계산하지 않는다.

공유 윈도우 검사는 과거의 고정 색상·반투명 재질 값을 앱에 강요하지 않는다. 동일한 LVRS 패키지에서 만든 기본 `ApplicationWindow`를 기준으로 윈도우·재질·색상 전달을 비교한다. 단일 공유 윈도우, 환경 설정의 소유권과 열기·닫기 동작은 계속 확인한다.
