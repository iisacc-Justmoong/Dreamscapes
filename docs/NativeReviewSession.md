# 생성 결과 검토의 네이티브 세션

## 범위

`src/App/Views/Result/NativeReviewSession`은 이미지와 비디오 생성 결과의 검토 상태를
Qt와 QML 없이 보관하는 C++23 모델이다. 제품의 `DreamscapesViewModelsNative`에 포함되며
iiSDKCore의 값과 조회 포트를 사용한다. 결과의 원본 메타데이터는 그대로 유지하고
선택·포커스·후보·제외·필터·정렬은 실행 중인 화면의 상태로만 관리한다. 모델은 저장소,
캔버스 문서, 생성 작업, Undo 기록에 쓰지 않는다.

기존 Qt 화면의 `GenerationReviewModel`은 네이티브 `Session`을 소유하는 호환 어댑터이다.
선택·필터·포커스 등 검토 상태의 단일 소유자는 세션이며, 어댑터는 Qt 모델 알림과
기존 화면이 요구하는 원본 `QVariant` 값을 제공한다. 동일한 세션을 LVUI 결과 그리드에
주입할 수 있지만 현재 제품 창은 여전히 QML 화면을 사용하며 LVUI 그리드를 생성하지
않는다. 제품 창의 작업 큐와 미리보기 연결, 비교·내보내기, 편집기 연결, 디자인 검증과
앱 전체의 Qt 및 LVRS 제거도 아직 완료되지 않았다.

## 상태와 화면 연결

- 제공된 Society 별칭의 `containerId`와 `key`를 우선하여 결과를 식별한다. 별칭이 없으면
  작업 ID와 원본 경로를 사용하고 미리보기의 URL 질의와 프래그먼트는 식별에서 제외한다.
- 여러 결과, 숨겨진 선택, 현재 포커스와 후보·제외 상태를 결과 키로 보관한다. 새 결과가
  도착하거나 필터·정렬이 바뀌어도 유지되는 결과의 검토 상태는 유지한다.
- `rowAt`은 가시 투영의 한 결과만 읽으며, Inspector는 원본이 제공하는 정보만 표시한다.
  값이 없으면 `Unavailable`, 복수 선택의 다른 값은 `Mixed`로 구별한다. 큰 정수 시드는
  부동소수점으로 바꾸지 않는다.
- 조회 포트의 변경 알림은 전체 투영 교체, 뒤에 추가된 행, 기존 행의 메타데이터·선택·
  포커스·검토 상태 변경을 구별한다. 포커스 이동만으로 전체 투영을 다시 만들지 않는다.
  네이티브 가상 그리드는 가시 항목만 조회하고 자체 스크롤 기준점을 보존해야 한다.
- `ReviewNavigation`은 제품 세션과 LVUI 값 계약을 적용한 iiGUI 컬렉션 탐색을 양방향으로 연결한다. 결과가
  바뀔 때만 원본 키와 짧은 화면 키의 대응을 갱신하며, 포커스 이동마다 전체 키 목록을
  새로 만들지 않는다. 긴 원본 경로도 줄이거나 파일에 기록하지 않는다. 제거된 행의
  늦은 입력은 세션에 적용하지 않고, 같은 원본이 다시 나타나도 이전 화면 키를 재사용하지
  않는다. 필터로 숨긴 선택과 범위 선택의 기준점을 함께 보존한다.
- 네이티브 탐색 상태는 세션에 한 번에 적용한다. 알 수 없는 결과 키는 전체 입력을
  거부하고 기존 선택과 포커스를 유지한다. LVUI 컬렉션의 단일 목록 제한은 65,536개이며,
  이를 넘는 제품 화면의 페이지 처리와 실제 위젯 연결은 아직 구현하지 않았다.
- 세션과 알림 수신자는 소유 스레드에서 조작한다. 수신 중 재진입하는 변경은 거부하며,
  구독은 약한 참조이다. 수신자 예외가 발생해도 나머지 수신자에게 알린 뒤 예외를
  전달한다. 예외는 이미 적용된 화면 상태를 되돌린다는 보장이 아니다.
- Qt 어댑터의 신호 처리 중 같은 어댑터에 들어온 상태 변경은 이벤트 루프에 예약한다.
  네이티브 세션을 직접 사용하는 수신자는 세션의 재진입 금지 계약을 따라야 한다.
  포커스만 변경된 경우 Qt 모델도 영향받은 행만 갱신한다.
- 키보드 명령은 텍스트 입력에 포커스가 있을 때 실행하지 않는다. 편집·비교 명령의
  대상은 원래 결과 값으로 반환하며, 실행 자체는 상위 화면과 기존 서비스의 책임이다.

## LVUI 결과 그리드 기반

생성 결과 그리드는 LVUI가 소유한 버튼·이미지와 iiGUI 가상 컬렉션을
사용하며, 생성된 화면과 독립 테스트 실행 파일은 LVRS 및 Qt를 링크하지 않는다.
기존 세션의 선택·필터·단축키와 외부 작업 핸들러를 보존한다. 이 계약은 기존 앱
전체가 네이티브 화면으로 전환되었다는 의미가 아니다.

네이티브 미리보기 공급자는 iiVisualCodec의 Image, iiNetwork와 iiFileProviderNative를
직접 찾는다. LVUI의 간접 의존성이 우연히 이 패키지들을 노출하는지에 의존하지 않는다.
이미지 형식에 독립적인 LVUI `ImageResolver<ii::gui::RasterImage>`와 LVUI 배포본의
앱 이미지 I/O 어댑터를 조합한다. 어댑터는 교체 가능한 별도 대상이다.
이 어댑터에는 `EventLoop::Sender`의 `on_signal`과 `signal`이 포함된 iiSDKCore
Runtime이 필요하다. 구버전과 같은 버전 번호만으로 이 API의 존재가 보장되지는 않는다.

기존 생성 결과 투영을 네이티브 검토 세션에 전달하는 C++ 어댑터는
결과 추가·제거와 기존 선택 상태를 동기화한다. 편집·비교·내보내기·상세 동작은
호출자가 주입하며, 원래 결과의 URL 및 불투명 메타데이터는 변환된 사본이 아닌
원본 값으로 반환한다. 연결이 해제되면 해당 동작과 갱신도 해제한다.

`NativeReviewGallery.lvui`는 LVUI와 iiGUI의 가상 컬렉션을 사용한다. 제품의 세션·선택과
탐색 스코프는 `bindNavigation`으로 연결하며, 일반 클릭은 포커스만 이동하고 Cmd/Ctrl·
Shift 클릭은 선택을 조작한다. 일반 포커스 이동은 다음 범위 선택의 기준점이 된다.
각 행의 선택·검토 정보는 원본과 분리된 세션 상태에서 읽고, 행의 식별자는 결과가
살아 있는 동안 유지한다. 숨겨진 결과가 바뀔 경우 오래된 미리보기 요청을 거부한다.

`ReviewGalleryModel`에는 원본 결과, 이미지 공급자 및 상세 보기·편집·비교·내보내기
핸들러를 호출자가 공급한다. 핸들러가 없는 동작은 비활성화한다. 결과 그리드는 실제
가시 행의 이미지 주소만 공급자에 요청하고, 응답이 준비되거나 공급자가 바뀌면 LVUI
바인딩으로 다시 그린다. 호출자가 래스터를 직접 제공하는 경우 기존 `setThumbnail`도
유지하며, 비동기 수신 시 원본 출처가 현재 결과와 다르면 적용하지 않는다. 새로운
출처가 들어오면 기존 래스터와 주소를 먼저 비운다. 생성 프로젝션 어댑터는 존재하지만
실제 앱에서 이를 생성하지 않는다. 기존 기능 연결 및 창 구성을 포함하는 제품 화면도
아직 구현되지 않았다.

`NativeReviewImages`는 LVUI `ImageIO` 계약·앱 이미지 I/O 어댑터와 iiSharedCanvas의 Qt 없는 네이티브 API를
조합하는 이미지 공급자이다. 앱은 iiGUI 호스트가 구동하는 `iiSDKCore::EventLoop`와
작업자 `Runtime`을 사용하여 `NativeReviewImages(loop, workers)`를 만들고
`setImageResolver(loader)`로 전달할 수 있다. 루프와 작업자는 로더와 모든 진행 중인
작업보다 오래 살아야 하며 루프가 계속 구동되어야 한다. 이미지 공급자 및 캐시 정책은
앱이 소유하며 테스트 바인딩이 제품 런타임에 자동으로 설치되는 것은 아니다.

기존 결과의 `image://iisc-preview/...`에 담긴 URL 안전 Base64 경로를 검증하고
로컬 `.iisc`에만 한정하여 LVUI 로더로 전달한다. 파일명과 개정 식별자가 캐시 구분에
반영된다. 일반 파일·URL은 LVUI 로더의 기존 정책으로 처리한다. 캔버스 읽기와 합성,
중간 PNG 인코딩 및 이미지 디코딩은 작업자에서 실행하며 중간 이미지는 메모리에만
둔다. 캔버스의 종횡비와 직선 알파를 보존하고 긴 변을 최대 512px로 제한한다. 고해상도
상세 보기의 원본 디코딩 경로를 대체하지 않는다. `.iisc`는 iiSharedCanvas의 읽기 전용
스냅샷 API를 사용하므로 원본을 변경하지 않는다. 공급자의 `invalidate`와 `clear`는
필요할 때 캐시를 명시적으로 무효화한다. 이 공급자는 아직 실제 앱 창이나 생성 결과
프로젝션에 설치되지 않았고, 제품 편집기 연결도 남아 있다.
`buildReviewGallery`는 LVUI로 생성된 뷰와 탐색을 연결한 다음 호출자의 설정 함수를
실행하는 C++ 진입점이다. 기존 세션을 전달하면 새 세션을 만들지 않고 공유하며,
생략하면 독립 세션을 만든다. Qt 화면과의 전환기에는 `GenerationReviewModel::nativeSession()`을
전달할 수 있다. 호출자는 화면의 모델을 통해 이미지 공급자와 작업 핸들러를 연결한다.
결과 목록의 `F`·`X`는 후보·제외 상태를, `C`는 연결된 비교 작업을 실행한다. `Space`는
선택을 바꾸지 않고 포커스된 결과를 상세 보기 핸들러에 전달한다. 텍스트 입력과 다른
네이티브 컨트롤의 키 입력은 가로채지 않는다. 상세 보기 화면 자체는 아직 연결되지 않았다.

`NativeReviewGenerationBridge`는 현재 `GenerationProjection`의 `reviewResults` 변경을
네이티브 세션에 반영한다. 이 전환용 경계만 Qt 값을 읽으며 LVUI 화면과 세션은 Qt와
LVRS에 의존하지 않는다. 원래의 `QVariant`를 결과 키로 보관하므로 액션은 URL과 불투명
메타데이터의 원래 타입을 받는다. 갱신이 알림 수신자의 예외로 중단되어도 실제 세션에
남은 결과와 일치하는 원본만 반환한다. 프로젝션 또는 어댑터가 종료되면 핸들러를
제거한다. 앱은 이 어댑터와 네이티브 창을 아직 생성하지 않는다.

기존 앱의 MCP 생성 제어는 현재 `GenerationController`, Qt 객체 및 iiMultimodalAgent의
Qt 기반 MCP 인터페이스에 결합되어 있다. 전체 전환에서는 인증·도구 스키마·생성 및 취소·
질문 응답을 포함한 기존 계약을 네이티브 백엔드에 연결하고 별도로 검증해야 한다.
이 결과 그리드 기반은 MCP의 이전을 수행하지 않는다.

## 검증

`Dreamscapes.NativeReview`는 선택·범위 선택·결과 추가·필터·정렬·알림 범위·
메타데이터·단축키·스레드와 수명을 검사한다. 1,000개 결과는 메모리 내 테스트 값이며
실제 대량 이미지의 디코딩 속도나 GUI 프레임 성능을 측정한 결과는 아니다.
`Dreamscapes.NativeReviewParity`는 현재 Qt 어댑터와 네이티브 세션을 같은 입력과 무작위
조작으로 비교한다. `Dreamscapes.NativeReviewBaselineParity`는 전환 전 Qt 모델을 고정된
테스트 기준으로 사용하여 회귀 여부를 독립적으로 비교한다. Qt는 이 비교 실행 파일에만
필요하며 네이티브 세션 자체의 의존성이 아니다.
`Dreamscapes.NativeReviewSharedSession`은 실제 제품의 Qt 모델이 소유한 세션을 창 없는
iiGUI 트리의 LVUI 그리드에 주입하여 결과 추가, 선택, 후보, 필터와 원본 URL을 보존하는
편집 대상을 양방향으로 검사한다. 운영체제 창이나 실제 앱에서 네이티브 뷰를 표시하는
것까지 검증하지는 않는다.
`Dreamscapes.ReviewWorkspace`는 기존 QML 화면에서 데스크톱·좁은 창·1,000개 결과의
검토 및 편집 경로와 이미지·비디오 제출 후 이동을 검사한다. 이 테스트는 허용된 계정
픽스처와 임시 Society 저장소를 사용하고 저장소 및 모델 목록이 준비되기를 기다린다.
라이선스 토큰 검증이나 실제 생성 모델 추론을 대신하지 않는다.
`Dreamscapes.NativeReviewNavigation`은 LVUI 탐색과 제품 선택의 왕복, 숨긴 선택, 신규·제거된
결과, 긴 원본 키와 종료된 행의 늦은 입력을 검사한다. 이 검사는 네이티브 위젯이나
운영체제 입력을 실행한 결과가 아니다.
`Dreamscapes.NativeReviewGallery`는 행의 식별자와 포커스, 필터, 늦게 도착한 미리보기,
원본 액션 대상과 연결 수명을 검사한다. `Dreamscapes.NativeReviewGalleryLink`는 생성된
LVUI C++ 연결과 실제 래스터 미리보기가 탐색 연결 교체 후 유지되는지 검사한다.
`Dreamscapes.NativeReviewRendererBoundary`는 LVUI에서 생성한 버튼과 iiGUI 이미지 위젯을 확인하고
macOS 실행 파일에 Qt 동적 라이브러리나 LVRS 정적·동적 심볼이 없는지 검사한다.
`Dreamscapes.NativeReviewGenerationBridge`는 실제 생성 프로젝션의 결과 갱신, 원본 값,
QUrl 미리보기 주소 전달, 선택·필터, 연결 종료와 예외 후 결과를 검사한다. 이 어댑터
검사에는 Qt가 필요하다.
선택한 iiGUI 라이브러리와 일치하는 내부 테스트 헤더를
`DREAMSCAPES_IIGUI_TEST_INCLUDE_DIR`로 명시하면 `Dreamscapes.NativeReviewGalleryWidget`이
iiGUI의 창 없는 검사 트리에서 클릭·범위 선택·키보드 명령·후보 버튼·필터·결과 추가,
편집 대상, 스크롤 위치, 1,000개 결과의 가시 행 활성화, 공급자 교체 및 늦은 이미지
갱신을 검사한다. `Dreamscapes.NativeReviewImageIO`는 저장된 PNG를 실제 앱 이미지 I/O 어댑터
작업자에서 읽어 네이티브 그리기 트리에 투영하고, 출처 교체 시 이전 이미지가 지워지며
결과 메타데이터는 바뀌지 않는지 검사한다. `Dreamscapes.NativeReviewIiscPreview`는 한글
파일명과 공백이 있는 직렬화된 `.iisc`를 작업자에서 읽어 알파가 있는 이미지를 표시하고,
같은 파일의 개정 변경, 잘못된 주소, 원본 바이트 보존을 검사한다. 별도로 커밋된 WAL이
있는 SQLite 작업 파일의 이미지를 읽고 데이터베이스와 WAL의 바이트가 바뀌지 않는지
확인한다. WAL에서 변경한 필드는 개정 번호이며 그림 픽셀을 WAL에서 변경하는 경우는
이 검사에 포함하지 않는다. 두 실행 파일의 직접 Qt 및 LVRS 의존성과 LVRS 정적 심볼도
별도로 검사한다. 이 검사들은 운영체제 창, 제품 앱의 서비스 연결 또는 시각적 디자인
동등성을 검증하는 것은 아니다.

Qt를 사용하지 않는 제품 뷰모델 기반과 기존 네이티브 회귀 검사도 프로젝트 루트의
`DREAMSCAPES_NATIVE_FOUNDATION_ONLY` 구성으로 빌드할 수 있다. 이 구성은 앱을
만들거나 설치하지 않는다. `LVUI_DIR`과 `iiGUI_DIR`에는 서로 호환되는 현재 LVUI·iiGUI
패키지를 지정한다. 위젯 검사에 쓰는 내부 헤더도 선택된 iiGUI 바이너리와 일치해야 한다.
기존 제품 빌드가 진행 중일 때 같은 `build/`를 재구성하지 않는다.

```sh
cmake -S . -B build -G Ninja \
  -DDREAMSCAPES_NATIVE_FOUNDATION_ONLY=ON \
  -DLVUI_DIR="<LVUI package>/lib/cmake/LVUI" \
  -DiiGUI_DIR="<iiGUI package>/lib/cmake/iiGUI" \
  -DiiSDKCore_DIR=$HOME/.local/SDK/iiSDKCore/lib/cmake/iiSDKCore \
  -DiiJson_DIR=$HOME/.local/SDK/iiJson/lib/cmake/iiJson
cmake --build build
ctest --test-dir build --output-on-failure
```

기본적으로 `DREAMSCAPES_NATIVE_REVIEW_IMAGES=ON`은 앱 이미지 I/O 어댑터가 포함된
LVUI 배포본, `LVUI::ImageIO`, iiGUI와 `iiSharedCanvasNative` 0.35 패키지를 요구한다. 이미지 공급자가 필요 없는 독립 모델
검사에서는 이 옵션을 `OFF`로 둘 수 있다. 실제 제품은 아직 별도의 레거시
`iiSharedCanvas::Quick`과 Qt 창을 사용하므로 두 경로의 바이너리나 검증 결과를 혼동하지
않는다.

기존 Qt 제품 구성의 두 비교 검사는 Qt 6.8.3을 사용하여 같은 입력에 대한 동작을 비교한다.
독립 모델 검사는 실제 GUI, 전체 제품 빌드, 시스템 설치 또는 다른 플랫폼 검증을 대신하지 않는다.
