# 사진·촬영 영상 가져오기 명령

`EditorCameraPhoto`의 명시적인 Import는 원본 획득과 문서 배치를 별도로 소유한다. `importStarted`에서 수락 토큰을 만들고, `EditorPhotoImportCommand`가 원래 문서의 세대·리비전·파일 경로, 배치 아트보드·크기·프레임레이트와 저장소 경로를 캡처한다. 캡처 시 전체 문서나 픽셀을 복사하지 않는다. 하나의 배치 소유자만 토큰을 인수할 수 있으며, 진행 중인 배치는 다시 클릭한 요청으로 교체하지 않는다.

사진 목록·썸네일·원본 내보내기·Photos 저장은 객체별 FIFO 도메인을 공유한다. 값형 Future 연속 작업을 앱 작업 풀에서 실행하므로, 화면 객체가 전용 작업 풀을 파괴하며 원본 내보내기의 종료를 기다리지 않는다. 닫힌 객체의 대기 작업은 실제 SDK 연산에 진입하기 전에 폐기한다. 실행 중인 SDK 연산의 즉시 중단과 프로세스 전체의 종료 대기는 별도 계약이다.

카메라 사진과 화면 캡처는 획득 직후 제공자 메모리에서 픽셀을 분리하고, 값으로 보유한 이미지·설정·임시 저장소·취소 플래그만 별도 작업자에게 전달한다. 사진의 비율·회전 변환과 PNG 인코딩·파일 쓰기는 화면 스레드에서 수행하지 않는다. 클라우드 원본 내보내기 뒤에서 캡처 저장이 기다리지 않도록 이 작업은 사진 라이브러리 FIFO와 분리한다. 저장이 끝나기 전에는 Busy를 유지하며 새 파일 경로를 발행하지 않는다. 연속 촬영은 해당 사진의 저장이 완료된 후 다음 사진으로 진행한다. 취소나 소유자 종료 전에 대기 중이던 저장 작업은 파일을 생성하지 않으며, 실행 중인 인코딩은 단계 사이의 취소 확인 뒤 결과를 폐기한다. 초기 픽셀 복사와 카메라 프레임의 이미지 변환, 영상 녹화 종료 시 썸네일 저장은 여전히 화면 이미지 경계에 남는다.

원본이 준비되면 URL 하나씩 현재 캔버스에 동기 전달하던 연결 대신, 원본 경로 묶음과 임시 파일의 공유 수명을 배치 소유자에게 전달한다. `preparePhotoImport`는 작업 스레드에서 이미지 디코딩, 네이티브 캔버스 첫 프레임 렌더링, 영상 디코딩과 관리용 이미지 래퍼 저장을 수행한다. 입력과 결과는 표준 C++ 값이며 QObject나 캔버스 주소를 작업자에게 전달하지 않는다. 이미지 코덱의 QImage 변환은 GUI 이미지 경계에 남는다.

사진은 원본 픽셀을 갖는 정적 비트맵 레이어로 배치한다. 촬영 영상은 기존 SDK의 512프레임·256MiB 디코딩 제한과 대상 문서의 프레임레이트를 유지하며, 프레임 배열을 갖는 VideoAsset/VideoLayer로 배치한다. EXIF 정규화와 촬영 시의 비율·회전 처리는 기존 획득 단계의 결과를 사용한다. 미리보기용 Mirror를 원본에 적용하지 않는다.

준비 결과는 원래 문서와 리비전·파일 경로가 같은지 확인한 후 소유 스레드의 한 문서 트랜잭션으로 적용한다. 최종 저장은 기존 동기 저장·충돌 검사·Undo 경로를 유지한다. 여러 사진은 한 번에 편집 이력에 반영한다. 아트보드를 탐색했더라도 캡처한 원래 아트보드에 배치하며 현재 보기를 강제로 이동하지 않는다. 사용자가 선택을 바꾸었다면 새 레이어 선택으로 덮어쓰지 않는다. 줌·팬·도구·선택·갤러리 필터 변경은 준비 작업을 재시작하거나 파일 상태를 발행하지 않는다.

문서 교체, 실제 문서 수정, 파일 바인딩 변경, 페인팅 시작 또는 명시적인 `cancelImport`는 이전 결과의 적용을 차단한다. 패널을 닫는 동작만으로 이미 수락한 원본 가져오기를 폐기하지 않는다. 작업 중 원본 경로의 정규 위치·크기·수정 시각을 재확인한다. 준비한 전체 배치가 유효한 뒤 관리 저장소로 진입하며, 저장소의 각 원본 래퍼는 기존 SDK 계약에 따라 개별적으로 지속 저장된다. 이후 취소나 문서 저장 실패가 이미 완료된 원본 래퍼를 되돌린다는 보장은 없다.

`PhotoOriginals::sourceLease`는 임시 원본 저장소의 수명만 보유한다. 획득 객체와 배치 객체를 닫아도 실행 중인 작업이 원본을 사용하는 동안 파일을 유지한다. 마지막 작업 입력과 소유권이 해제되면 설치된 iiFileProvider 네이티브 임시 디렉터리가 정리한다. 썸네일과 Photos 저장 작업도 사용하는 임시 파일의 수명을 직접 보유한다.

배치 결과가 적용된 다음 기존 `importReady` 관찰 알림을 발행한다. 이 알림을 다시 픽셀 편집 명령으로 연결하지 않는다. 완료·취소·실패 관찰자에서 새로운 요청을 시작하거나 객체를 삭제하면 이전 호출이 새 상태를 덮어쓰지 않도록 토큰과 생존성을 확인한다. 작업 실패는 획득 UI에 전달하며 대기 중이던 캔버스의 오류·리비전·파일 내용을 임의로 변경하지 않는다.

가져오기 실패는 별도의 `importError`로 보유하므로 카메라 보기 전환이나 캡처 오류 초기화가 완료 결과를 지우지 않는다. Gallery/Capture 보기에는 숨은 카메라 VideoOutput을 생성하지 않는다. Camera 보기의 Loader가 미리보기 객체를 소유하고, 해제 시 자신이 부착했던 출력만 분리한다. 이전 출력의 파괴 알림이 새 출력의 연결을 해제하지 않는다. 패널 전체 파괴 시 기존의 캡처 취소 정책은 유지하며, 이미 수락한 문서 가져오기와 구분한다.

`Dreamscapes.PhotoImport`는 실제 원본 픽셀, 문서 교체 폐기, 작업자 실행·UI 이벤트 처리, 파일 무변경, 원래 아트보드 배치, 취소와 다음 요청, 소유자 비대기 종료와 임시 파일 수명, 한 번의 배치 저장·Undo·재열기, 실패 후 재시도와 수락 관찰자의 삭제, 서로 다른 영상 프레임의 실제 디코딩을 검사한다. 캡처 저장은 작업 풀을 차단한 상태에서 파일 미발행·화면 이벤트 처리를 확인한 뒤 정상 저장, 취소, 소유자 종료와 저장 실패 후 재시도를 검사한다. 실제 QML 패널 검사는 Gallery의 숨은 카메라 객체 부재, 대기 중 Import 비활성화, 문서 교체와 패널 종료 시의 적용 정책을 확인한다. 실제 카메라·Photos 권한·화면 캡처, 큰 문서의 최종 저장 지연과 앱 전체 종료 시간은 이 검사의 완료 주장에 포함하지 않는다.

## 갤러리 보기 요청의 작업 수명

목록을 다시 불러오면 이전 목록과 그 목록의 썸네일이 공유하는 값형 취소 플래그를 설정한다. FIFO의 대기 작업은 SDK에 진입하기 직전에 이 플래그를 확인하여 오래된 보기 요청을 건너뛴다. 이미 실행 중인 SDK 호출은 강제 중단하지 않으며, 스캔이 끝난 뒤의 목록 구성이나 로컬 폴더 순회는 단계 사이에서 폐기를 확인한다. 완료 알림의 기존 갤러리 세대 검사도 유지한다.

수락한 원본 가져오기와 Photos 저장은 갤러리 취소 플래그를 사용하지 않는다. 목록 새로고침은 원본 요청의 취소나 재시작으로 이어지지 않는다. 필요한 썸네일과 파일 작업은 같은 직렬 도메인에서 기존 순서를 유지하며, 오래된 썸네일만 실제 SDK 작업을 생략한다. 추가 작업 풀이나 GUI 객체 참조를 작업자에 전달하지 않는다.

`Dreamscapes.PhotoImport`는 연속 목록 요청의 중간 스캔 생략, 오래된 썸네일 뒤에 수락한 원본의 실제 호출 순서, 현재 썸네일의 FIFO 보존, 실행 중 원본을 유지하는 목록 새로고침을 검사한다. 차단된 SDK 호출 중 화면 이벤트 처리도 확인한다. 실제 Photos·iCloud의 지연이나 전체 앱 FPS 개선율을 이 검사로 환산하지 않는다.

## 목록 표시와 파일 명령의 분리

사진 카탈로그는 C++의 `EditorPhotoGalleryModel`이 표시용 순서·행 상태·선택 개수와 기존 값 목록의 캐시를 소유한다. 타일 갱신과 선택·검색·정렬은 이 모델만 갱신하며 파일 작업자를 발동시키지 않는다. 수락한 가져오기는 모델의 원본 목록에서 선택된 레코드와 기존 원본 토큰·임시 파일 수명을 캡처한다. 이후의 보기 갱신은 그 배치를 다시 구성하지 않는다. 원본 준비·큐의 직렬성·명시적 취소·원래 문서 배치 계약은 유지한다.

`Dreamscapes.CameraPhoto`는 변경 행 알림·초기화 부재, Qt 모델 규약, 정렬·필터와 기존 목록의 일치, 동일 필터 무알림, 선택 개수, 알림 중 필터 변경·소유자 삭제, 획득 오류 관찰자의 새 요청·삭제와 모델 게시 중 준비 오류 보존을 검사한다. `Dreamscapes.EditorCameraPhoto`의 실제 Gallery 패널 검사는 400개 원본 카탈로그의 가상화, 썸네일 한 개 완료·선택 변경 때의 타일 수명과 바인딩, 검색 결과를 확인한다. UI 생성 카운터만 삽입하며 실제 패널의 실행 로직과 원래 URL·이미지 경로를 유지한다.

## 보기 종료와 승인 완료의 처리 경계

권한 승인의 완료는 실제 목록 조회까지 연결한다. 현재 Photos 보기가 유효할 때만 조회하고, 숨기거나 닫은 보기의 완료로 새 스캔을 시작하지 않는다. 사용자가 다시 들어오면 현재 권한과 새 읽기 수명으로 요청한다. 파일 작업은 갤러리 표시 객체의 종료와 분리한다. 실제 타깃 캔버스를 갖는 검사에서 오래된 썸네일은 건너뛰고 이미 수락된 원본을 원래 문서에 한 번 배치하는지 확인한다.

`Dreamscapes.CameraPhoto`는 오래된 권한 요청·중복 응답, 최신 Photos와 로컬 보기, 승인·제한·거부·미지원, 예외 후 재시도와 지연 완료, 소유자 삭제와 다른 스레드의 완료를 검사한다. 또한 현재 표시 객체의 해제·파괴·교체, 비활성 읽기와 썸네일 출력 부재, 캐시된 목록의 재연결을 검사한다. `Dreamscapes.PhotoImport`는 보기 해제 뒤에도 원본이 한 번 적용되는지와 취소된 캐시 썸네일을 현재 요청만 다시 읽는지 검사한다. 썸네일의 JPEG 검사는 실제 생성·크기·색상 특성을 확인하며 손실 코덱의 작은 색상 반올림을 허용한다.

실제 패널 검사는 권한 버튼을 통해 요청하고 현재 보기·Photos 복귀·로컬 유지·거부·숨김·닫힘을 각각 실행한다. 제어된 제공자를 사용하므로 물리 장치나 실제 OS 권한 팝업의 승인을 검증했다는 의미는 아니다.
