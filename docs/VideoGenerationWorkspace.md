# Video generation workspace

The desktop sidebar's **Video** entry opens a dedicated, retained workspace for precise video generation parameters. Its layout follows the canvas and timeline from Figma `464:9774` and the generation inspector from `515:89044` in the existing Dreamscapes window. Design examples are not templates or initial draft data. Home's QuickGenerate and mobile Video shortcut retain their existing queue/result path.

## Layout

The workspace uses a 16 px inset, a preview column, a fixed 300 px inspector, and an independent timeline below both columns. The inspector scrolls vertically without moving the preview or timeline. The preview fits one scale to the selected output dimensions, preserving aspect ratio. Large workspaces preserve the design's 116 px gap between preview and inspector; smaller workspaces use 24 px. Narrow windows scroll a minimum 720 px workspace rather than stack or overlap the inspector. A short window scrolls a minimum 660 px workspace, increased as needed to preserve at least 210 px above the timeline. The shared timeline height follows only user-defined tracks; there are no default track rows. Controls and the footer wrap as its available width decreases. Ruler and tracks fit that width at the default scale. Only zooming introduces horizontal scrolling inside the tracks, while headings and controls remain in place.

All text, controls, menus, field materials, colors, spacing and interaction feedback reuse the installed LVRS package. A new workspace has a blank preview and empty shot/keyframe collections, no selection, and a playhead at F000. Preview images and shot thumbnails only use user-selected image conditions or actual generated output. No design sample image is displayed.

## Editing and generation

`VideoTimelineState.qml` starts with an empty track list. **+ Track** adds a named Shots, Contents, Audio or Caption track. Tracks stay in that type order; position controls reorder tracks within their type. Shots/image keys reference stable track IDs, and image conditions are never distributed by a fixed numeric lane. Track edits and deletion participate in undo/redo. Audio/Caption rows have no initial placeholders.

`VideoTimelineState.qml` owns shot boundaries, selection, excluded/locked state, per-shot prompts, image keyframes, frame numbers, image condition weights, undo and redo. The empty timeline's ruler reflects duration × FPS without creating shots. Generating from an empty shot collection uses the composition prompt, duration, FPS and explicitly added image conditions in one internal generation segment; submission never inserts that segment into the draft. Only **+ Shot** creates a visible shot, and its first shot spans the current generation duration. User-added kept shots are concatenated in timeline order. Splitting, trimming, rolling a boundary, sliding a shot, duplicating and ripple deletion change that draft. Changes are bounded to at least two output frames per shot. Deleting the final shot returns to an empty timeline. Keyboard controls include V/B, frame arrows, I/O, Space and undo/redo. The Generation/Shot inspector tabs share the selected shot. Image conditions can be chosen at the first, last or current frame, dragged, nudged, weighted, copied, pasted and deleted; their initial strength is the runtime default of 1.0.

The inspector exposes width/height, duration/FPS, count, steps, CFG, seed, interpolation, temporal decoding, execution and H.264 quality/preset. Defaults match `normalizeVideoRecipe`: 1024 × 576, 5 seconds, 24 FPS, one output, 30 steps, CFG 3 and a random seed (`-1`), with the existing decoding/execution/encoding defaults. Prompt and negative prompt start empty unless the user configured defaults in Preferences. No example negative prompt or fixed seed is injected. Camera motion parameters and a Camera/Zoom track are omitted. Width and height must be divisible by 32; invalid fields block submission. Duration/FPS resize the draft's frame extent even when it contains no shots. **Reset defaults** restores generation defaults and clears tracks, shots, keyframes, selections, clipboard, undo/redo, playback and timeline zoom. The workspace has no template or saved-recipe controls and does not read or write the former `VideoGeneration/savedRecipe` setting. Existing saved settings are left untouched. Navigation retains user edits after first opening.

`GenerationController::enqueueVideoRecipe` validates a complete immutable submission, copies every image condition to Society's GenerationInputs, and creates the existing serial queue. The controller writes an SDK storyboard into its job workspace with kept shots, shot prompts, per-shot frame counts, local image conditions and weights. It forwards every exposed runtime parameter to the installed iiLocalDiffusion video launcher. Queue ownership stays in the Video workspace, so generation does not navigate to the Home result screen. All requested output variations stay selectable and playable in the preview; cancellation uses the existing queue cancellation and **Save video** exports the verified MP4 bytes.

Audio and Caption rows exist only after the user adds tracks and show empty states. Audio mixing, caption rendering and text overlays are not implemented by this generation workspace. The weight view displays image condition anchors; arbitrary curve interpolation is not sent to the LTX SDK.

## Verification

The Video workspace uses `VideoTimeline.qml` and `VideoTimelineState.qml` for
its generation recipe. It retains empty generation defaults and user-defined
Shots/Contents/Audio/Caption tracks. The editor's finalized Figma design
`1065:90081` is implemented separately by `EditorTimeline.qml` and
`EditorTimelineModel`: its **Layers** rows read and edit the actual native IISC
canvas rather than a generation draft. The two consumers share LVRS controls
and fixed button-state policy, while preserving these different data contracts.
See [EditorLayout.md](EditorLayout.md#bottom-timeline).

Frame-rate controls in this workspace and Home QuickGenerate offer 12, 24, 30, 60 and 120 FPS; the default remains 24 FPS. Both submission APIs accept the same set, including 30 seconds at 120 FPS. An FPS edit changes the empty timeline's frame extent without adding shots or keys. The interpolation factor is a minimum: iiLocalDiffusion automatically increases source-frame spacing for high output rates, limits current LTX source generation to its nominal 25 FPS policy and interpolates to the requested final FPS. The UI forwards the request and does not implement interpolation. SDK planning, local/remote request and real FFmpeg media regressions cover 60/120 FPS, anchor preservation and unchanged output timing; product queue and GUI regressions cover both controls and final FPS metadata.

The fitted preview frame stays centered horizontally and vertically inside the preview surface, independently of the inspector and timeline. The workspace regression checks 1:1, 16:9, 9:16, 4:1 and 1:4 output ratios across four window sizes, including the narrow scrolling workspace, and verifies both centering and containment. `DREAMSCAPES_CENTER_CAPTURE_DIR` captures these ratio variants in an existing directory under `build/`.

Invalid numeric edits block generation. **Reset defaults** clears the field error and restores the displayed value; the workspace regression test exercises the visible reset button.

Disabling **Random seed** requires an explicitly entered nonnegative fixed seed when the draft still has the random sentinel `-1`. The UI marks that seed invalid and blocks submission instead of inserting a fixed value or continuing to generate randomly. Re-enabling random seed clears that requirement. After user shot edits, duration/FPS changes also update the generation extent used when the last shot is deleted, even if the requested frame count already matches the edited shots. Undo/redo keeps duration, FPS and that frame extent synchronized.

`Dreamscapes.Video` runs the retained Home video queue/player/export path, `videoWorkspaceStartsEmptyAndUsesGenerationDefaults` and `videoWorkspaceRoutesEditsAndGenerates`. The empty-state regression verifies blank previews and collections, absence of recipe-saving controls, default parameters, duration/FPS edits without inserting shots, explicit image conditions without shots, deletion of the final shot, undo/redo, complete default reset and a normal generation submission from an empty timeline. The workspace test opens the real sidebar entry, asserts the 300 px inspector and measured timeline height, responsive control wrapping, independent scrolling and aspect fit, explicitly adds its editing fixture shots, exercises split/undo and image frame/weight editing, checks draft retention and resized windows, and verifies kept-shot/image-condition values in the accepted queue. It then runs the deterministic process fixture to produce and decode MP4, checks workspace result ownership, plays the output and records optional screenshots via `DREAMSCAPES_CAPTURE_DIR`. Fixture output proves request and UI plumbing, not learned LTX image quality.

`videoRecipeValidatesRuntimeContract` checks dimensions, numeric types and limits, enum validation, duplicate/out-of-range image frame anchors and shot-count/frame-count constraints. Existing video queue tests continue to verify immutable first-frame copying, bad output rejection and cancellation. A real installed LTX model invocation remains a distinct runtime smoke check.
