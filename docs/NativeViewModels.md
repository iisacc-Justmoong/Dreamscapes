# 네이티브 뷰모델과 QML의 경계

Dreamscapes의 화면 상태 계산과 명령 조합은 C++23 뷰모델이 소유한다. QML은 LVRS를 이용한 배치, 바인딩, 입력 전달, 포커스·스크롤·팝업 및 화면 그리기를 담당한다. QML 함수 이름을 유지한 얇은 전달 함수는 기존 화면·테스트의 호출 계약을 보존하기 위한 것이다. 전달 함수 안에 도구 설정 복사, 파라미터 검증, 생성 레시피 조합 또는 파일 목록 정렬을 다시 넣지 않는다.

## 모듈 구조

| 계층 | 소스/타깃 | 책임 |
|---|---|---|
| 순수 네이티브 모델 | `src/App/ViewModels/Native`, `DreamscapesViewModelsNative` | iiSDKCore Value, 타입이 명시된 QueryPort, 초안·선택·타임라인·상태 투영. Qt 링크 없음 |
| 화면 바인딩 | `ViewData`, `VideoTimelineModel`, `GenerationProjection`, `SnapshotListModel` | QVariant 변환, 속성별 변경 통지, QAbstractItemModel 알림 |
| 표시 조회 | `Native/ViewProjection`, `ViewProjectionModel` | 메뉴·모델·선택·목록 범위·알림·비디오 행 배치의 네이티브 조회와 원본 항목 복원 |
| 비디오 재생 시계 | `Native/TimelinePlayback`, `TimelinePlaybackModel` | 단조 시각 기준 프레임·반복·종료·스냅 계산, GUI 타이머의 깨우기 연결 |
| 앱 명령 연결 | `WorkspaceSession`, Generation 및 Editor/Home의 `*Model` | 네이티브 모델의 결과를 기존 생성·문서·스토리지 인터페이스로 전달 |
| 뷰 | `src/App/**/*.qml` | 화면 계층과 표시, 입력 이벤트를 위 모델로 전달 |

하위 네이티브 모델은 GenerationController, EditorCanvas, QObject 또는 QML을 참조하지 않는다. 단위 변환과 기존 프리셋 공급자가 필요한 CanvasDraft는 함수 인터페이스를 주입받는다. 그래픽 초안도 ToolRead/ToolWrite 계약에만 의존한다. 파라미터 조회는 필요한 입력 스냅샷만 읽으며, 조회마다 다른 패널의 표시 투영을 다시 만들지 않는다. QObject 연결부는 Qt GUI가 남아 있는 동안의 경계이며, 전체 앱의 Qt 독립이 완료되었다는 의미가 아니다.

## 실행과 소유권

짧은 선택·탐색·초안 편집은 소유 스레드에서 `QueryPort::send()`로 실행한다. 모든 클릭을 작업 스레드로 보내고 동기 대기하는 구조는 사용하지 않는다. 반환값은 이미 컴파일된 C++ 수신자가 계산한다. QJSEngine으로 JavaScript를 실행하여 결과를 얻는 생산 경로는 없다.

파일 목록의 필터·정렬·선택 투영은 `ViewRuntime.cpp`의 공용 `ii::runtime::Runtime`에서 실행한다. 작업자는 2개, 재사용 작업 슬롯은 64개이다. StorageBrowserModel은 분리된 값 스냅샷만 보낸다. 작업자는 QObject, 문서, 드라이브 핸들 또는 파일 API를 읽지 않는다. 화면별 실행 중 요청은 하나로 제한하고, 후속 입력은 최신 요청으로 합친다. 세대 번호가 바뀐 결과는 버린다. 드라이브가 바뀌면 이전 목록을 먼저 제거한다.

모델 파괴 시 QueryPort의 close 장벽을 거친다. 작업 완료 후 GUI 알림은 수신 객체를 컨텍스트로 지정하므로, 이미 파괴된 화면에는 배달되지 않는다. 이 경로를 수정할 때 소유자 종료·취소·늦게 도착한 결과를 함께 검증해야 한다.

기존 추론, 캔버스 렌더링, 픽셀 편집과 미디어 작업자는 기존 네이티브 백엔드를 계속 사용한다. 이번 뷰모델 분리로 모든 기존 백엔드 작업이 새로운 작업 풀로 이전되었다고 해석해서는 안 된다.

## QML 계산의 최종 경계

프레임·퍼센트·ControlNet 및 LoRA 가중치의 문자열 해석은 `NumberInputs`의 네이티브 조회에서 수행한다. 프레임 입력은 정수, `F024`, `24f`, `Source F024` 형식을 지원하며 일부 숫자만 있는 문자열·소수·범위 초과 입력을 거부한다. 거부된 값은 초안과 문서를 유지한다. 레이어 불투명도의 재입력은 현재 표시값과 같으면 편집 명령을 만들지 않는다. QML에서 NaN을 만들어 파라미터로 전달하지 않는다.

모델 이름과 ID 목록, 선택 인덱스, 플랫폼 리뷰의 작업 필터, 출력 개수 정렬, 알림 문구, 파일 목록 범위 및 메뉴 항목의 값 변환은 `ViewProjection`의 타입이 정해진 `QueryPort`에서 실행한다. QML 바인딩은 입력 목록·선택 ID·표시 모드를 인자로 명시한다. C++ 호출 내부를 QML이 자동 추적한다고 가정하지 않는다.

범위 선택과 조회는 네이티브에서 결정한 인덱스로 **원래 QVariant 항목**을 반환한다. URL·날짜·임의 메타데이터를 문자열이나 축약된 객체로 바꾸지 않는다. 조회 수신자는 문서·파일·생성 백엔드에 접근할 인터페이스를 갖지 않는다. 목록 투영의 최대 입력은 1,048,576개이며, 초과 요청은 부분 결과나 대규모 할당을 수행하지 않고 거부한다.

비디오 타임라인은 QML `Timer`와 `Date.now()`로 재생 프레임을 계산하지 않는다. `TimelinePlayback`이 `std::chrono::steady_clock` 경과 시간으로 현재 프레임을 계산하므로 늦은 깨우기는 실제 경과한 프레임으로 건너뛰며 지연을 누적하지 않는다. `TimelinePlaybackModel`의 Qt 타이머는 GUI 스레드를 깨우는 연결부이다. 화면 비활성화, 타임라인 교체·초기화·파괴 시 재생을 중단하며, 늦은 깨우기가 재생을 다시 시작하지 않는다. 시킹과 재생은 문서 편집이나 Undo 항목을 만들지 않는다. 분수 FPS의 시간 코드는 반올림한 명목 FPS 기준이며 드롭 프레임 표기를 의미하지 않는다.

그레디언트 기본 프리셋은 `background-defaults.json`에 존재한다. `BackgroundPalette`가 기본·저장 프리셋을 합치고 색상에서 정규화한 정지점을 만든다. 색상이 하나인 경우 위치는 0이며 0으로 나누지 않는다. 레이어 그룹의 펼침·접힘은 `EditorToolState`의 세션 표시 상태에만 저장하고 문서 설정·픽셀 편집으로 전달하지 않는다.

QML에 허용되는 함수는 네이티브 호출의 전달, 화면 포커스·팝업·스크롤·배치와 그리기이다. 렌더링된 자식 버튼의 실제 너비를 모으거나 남는 공간을 계산하는 `EditorToolControl`·`EditorTimeline`의 배치 계산은 뷰의 책임이다. 이러한 GUI 객체를 순수 모델로 넘겨 결합시키지 않는다. `test_native_view_boundary.py`는 이 세 가지 배치 표현식을 제외한 QML의 데이터 reducer 재도입과 비디오 JavaScript 재생 시계를 차단한다. 함수 개수만으로 네이티브 이전율을 계산하지 않는다.

## 이전된 화면 계약

- **Home:** 프롬프트 기본값, 사용자 프롬프트 보호, 미디어 종류, 종횡비와 출력 크기, 개수·시드·프리셋·첨부 및 생성 요청 조합은 GenerationComposerModel이 담당한다. 데스크톱과 간소화된 입력창은 동일한 네이티브 초안 소유자를 공유한다. 공유 관계의 순환을 거부한다.
- **이미지/비디오 생성:** 입력 유효성, 기존 고급 이미지 설정, 비디오 duration/FPS/카메라 조건, 프리셋과 이미지 키프레임 및 제출 작업 ID는 네이티브 모델이 소유한다. 실패한 비디오 크기 변경은 초안과 타임라인의 일부만 변경하지 않는다.
- **진행/검토:** 제출한 ID에 속하는 결과·진행 상태만 해당 화면의 소유로 취급한다. 검토 선택·제외와 키보드 명령은 네이티브 Selection/ReviewCommands를 사용한다. 필터나 결과 추가로 기존 ID를 잃지 않는다. 원본 파일을 수정하지 않는다.
- **파일 보기/열기:** 정렬·필터·현재 디렉터리와 선택은 StorageBrowserModel에 있다. WorkspaceSession은 실제 열기, 지연 다운로드, 편집기 연결을 담당한다. 취소는 키와 컨테이너 ID가 모두 일치하는 소유 다운로드만 중단한다.
- **Home 목록과 큐 집계:** 최근 파일의 종류 필터·선택 ID 조정·메타데이터 병합과 큐 상태 집계도 NativeData의 타입별 QueryPort 수신자가 계산한다. 연결부는 네이티브에서 결정한 인덱스에 따라 원래 QVariant 항목을 반환하여 URL과 추가 메타데이터를 보존한다.
- **새 캔버스:** 카테고리·검색·프리셋·입력 문자열·단위 변환·유효성·생성 사양은 CanvasDraft/NewCanvasModel에 있다. 다이얼로그는 사양 신호를 전달한다.
- **에디터 도구:** ToolStateModel/EditorToolState가 도구별 초안, 실제 선택 도형의 크기, 텍스트·컴팩트·카메라 표시값을 투영한다. QML 초기화 순서와 관계없이 카탈로그 연결 이전 입력을 보존한다. Undo의 문서 설정을 받을 때 독립적인 그래픽·사진 획득 초안을 유지한다.
- **그래픽 도구:** GraphicDraft는 뷰·연산·컬렉션·중첩 경로·기본값·검증과 액션 계획을 담당한다. GraphicDraftModel은 기존 네이티브 helper/image 작업자를 소유하며, 컨텍스트가 달라진 결과를 채택하지 않는다. 샘플링·파일·컬러 피커의 결과 채택도 C++에서 수행한다.
- **배경/마스크/레이어:** 색상 SDK 연결과 스와치·그레디언트, 제거·대체·마스크 명령, 레이어 조정값은 네이티브 연결부를 통한다. 마스크 목록은 안정적인 ID를 갖는 네이티브 행 차이를 적용한다.
- **비디오 타임라인:** tracks/shots/keys, 선택, 스냅, 복사·붙여넣기, 트림·분할·리플 편집과 Undo/Redo는 VideoTimeline이 소유한다. 빈 초기 트랙을 유지한다. 클립보드 활성 여부와 현재 프레임의 참조 이미지도 네이티브 파생값이다.
- **Publish:** 기존 iiSocialPublish 실행/검증 경계를 유지하면서 플랫폼·계정·태그·표지 선택 투영을 C++로 이동한다.

## 뷰 상태와 파일 상태

제출 오류의 수명은 GenerationSubmissionModel이 소유한다. 이미지·비디오 입력이
실제로 유효해지면 유효성 오류와 해당 표시 문구만 한 번 해제한다. QML은 읽기
전용 `invalidInputSubmission`에 값을 대입하지 않는다. 기존 수락 작업 ID와
결과 선택을 유지하며 입력 수정 때문에 생성 제출·취소·파일 저장을 호출하지
않는다. 런타임 오류는 입력 수정으로 지우지 않고, 이전 입력 객체의 알림도 새
입력의 오류를 변경하지 않는다. 연결부 회귀와 실제 고급 생성 화면에서 확인한다.

View Options의 보조 입력(type·units·orientation)이 빈 문자열이면 생략된
입력과 같은 기본 카탈로그 키로 정규화한다. 해당 가족에서 사용하지 않는 값을
QML이 빈 문자열로 전달해도 Snap·Grid·Guides의 전체 컨트롤을 유지한다.
순수 네이티브 검사와 기존 모든 보기 옵션 상태 검사로 확인한다.
도구의 전체 컨트롤 조작 검사는 실제 데스크톱 Flickable을 스크롤하여 대상을
노출한 뒤 클릭한다. 창 밖 좌표를 보내지 않으며 기존의 값·액션 ID·초안 유지
단언은 그대로 검사한다.

그래픽 원본 선택은 공개된 `sourceRequested`와 `acceptSource` 계약으로 검사한다.
대화상자를 열고 취소하면 초안을 유지하며, 원본을 수락하면 요청한 연산의
`map` 파라미터만 변경되는지 연결부에서 확인한다. 화면에서 제거된 내부 상태
속성을 테스트 목적으로 다시 노출하지 않는다.

독립 타임라인·보기 옵션·색상 선택 화면 검사도 `NativeData`를 등록한 뒤 QML을 생성한다. 실제 앱과
다른 등록 상태에서 발생한 ReferenceError를 허용하지 않는다. 새 GUI 회귀 함수는
CTest 그룹에도 등록하여 전체 검사에서 누락되지 않도록 한다.

QStringList 속성이 QML을 거쳐 네이티브 투영 메서드로 들어오는 경계도 검사한다.
색상 모드의 실제 문자열 목록을 사용해 선택 인덱스와 선택 표시 문자열의 순서,
선택 변경 후의 재평가를 확인한다. 순수 C++ QVariantList 입력만으로 화면의
문자열 시퀀스 전달까지 검증했다고 간주하지 않는다.
Qt의 시퀀스 연결부가 항목을 QVariant 안의 QVariant로 전달하는 경우에는
공개된 QVariant 추출 API로 내부 값을 해제한 후 같은 네이티브 변환을 적용한다.
이 래퍼를 문자열로 직접 변환하여 빈 값으로 잃지 않는다. 일반 입력과 중첩
래퍼 입력이 같은 값을 만드는지, 실제 QML 메뉴·선택·타임라인 경로에서 같은
선택 인덱스가 전달되는지 검사한다. 배열 변환은 항목 수만큼 한 번 예약하여
항목을 추가할 때 반복적으로 버퍼를 확장하지 않는다.

`Dreamscapes.ViewCatalog`는 실제 그래픽 패널 381개의 ID·이름 별칭과 조회 결과의
독립성을 검사한다. 호출자가 반환 스냅샷을 편집해도 원본 카탈로그는 유지되어야
한다. `build/DreamscapesViewCatalogTests --measure`는 동일한 원본 데이터에서
수신자 구성과 단순 메타데이터 조회 1,000회의 시간·결과 체크섬을 기록한다.
`--measure-indexed`는 이어서 실제 패널의 ID·이름 별칭을 모두 조회하여 그래픽
색인을 사용한 상태의 프로세스 최대 메모리도 비교할 수 있게 한다. 시간은 통과
조건으로 사용하지 않는다.

`ViewData`는 생성 시 11개 JSON 파일을 모두 파싱하지 않는다. 네이티브
`ViewCatalog`에 값 로더를 주입하고, 각 리소스를 처음 조회할 때만 번들에서 읽어
인스턴스 안에 보관한다. 파일 경로·이미지 소스·표시 메타데이터 같은 순수 투영은
카탈로그를 하나도 읽지 않는다. 기존에 값을 전달한 생성 방식도 유지하며, 전달된
값이 로더보다 우선한다. QML 엔진이나 수신자 사이에 변경 가능한 전역 캐시는 없다.

도구·그래픽 색인도 해당 기능을 처음 사용할 때 구성한다. ID·이름·중첩 행·편집기
색인은 소유 중인 불변 값의 참조만 저장하고, 연산 기본값은 필드별 최초 값을 한 번
모은다. 패널 기본값의 중첩 행 우선순위와 편집기의 최초 일치 순서는 유지한다.
참조는 수신자 밖으로 반환하지 않으며, 조회 결과는 수신자 소멸 후에도 유효한
독립 값이다. 이 수신자는 소유 스레드에서 사용하고, 자신을 참조하는 조회 포트를
유지하므로 복사·이동하지 않는다. 회귀 검사는 필요한 도메인만 한 번 로딩되는지,
다른 리소스가 추가되어도 색인의 참조와 인스턴스별 격리가 유지되는지 확인한다.

네이티브 경계 정적 검사는 한 번 수집한 소스 스냅샷을 모든 규칙에서 재사용한다.
같은 QML을 규칙마다 다시 탐색·읽지 않으며, 필요한 독립 파일 읽기는 최대 8개로
제한한다. 실제 프로덕션 소스는 한 번씩만 읽고, 검사 대상이 아닌 테스트 C++와
이미지는 읽지 않는다. 별도 계약 검사는 공유 스냅샷에서도 QML 리듀서·레거시
스크립트 평가·네이티브 Qt 참조·JS 모듈 회귀가 계속 거부되는지 확인한다.

2026-10-27 Release 네이티브 소비자를 새 프로세스에서 전후 교대로 3쌍 실행한
측정에서 수신자 구성의 중앙값은 8.246 ms에서 0.042 ms로, 같은 소스 조회
1,000회는 2.237 ms에서 0.279 ms로 줄었다. 입력 11개 JSON의 파싱은 두 구성
모두 구성 타이머 전에 완료했으며 결과 체크섬은 21,000으로 같았다. 실제 패널
381개의 ID·이름을 전부 조회해 그래픽 색인까지 사용한 프로세스의 최대 RSS
중앙값은 32,997,376 bytes에서 14,155,776 bytes로 줄었다. 이는 동일한 네이티브
카탈로그 작업의 측정이며 앱 전체 메모리, 화면 프레임 시간, 추론 처리량을 뜻하지
않는다. 원본 실행 로그와 바이너리 해시는 `build/optimization-20261027/catalog-comparison.json`에 기록한다.

새 생성 제출이 수락되면 네이티브 제출 모델의 초기화 신호에 따라 비디오 재생과 이전 저장 완료 문구를 초기화한다. 입력 검증 실패나 제출 거부 시에는 현재 결과·선택을 지우지 않는다. 비동기 파일 화면의 회귀 검사는 실제 목록 도착을 기다린 뒤 개수를 검증한다.

조회, 정렬, 필터, 선택, 팝업, 미리보기 컨텍스트 변경에는 문서 저장 인터페이스가 없다. EditorToolState의 acceptedSelection은 실제 문서 상태를 받아 표시값만 동기화한다. 명시적인 사용자 편집 명령의 ToolReply만 기존 EditorCanvas 편집 인터페이스로 전달한다. 세션 검토 상태는 원본의 게시 메타데이터와 별개이다.

명시적인 도형 편집은 메서드가 반환되기 전에 실제 캔버스에서 수락된 값을 다시 동기화한다. 외부의 선택·문서 변경 알림은 큐에서 합치되, 방금 입력한 width/height를 이전 선택값으로 덮지 않는다. 비디오 타임라인의 프레임 범위 문자열 검증과 전체 선택 역시 네이티브 명령으로 수행한다.

뷰 단위 초기화는 하나의 초안에서 모든 필드의 변경 계획을 만든다. 연결부는 연속 필드 편집 사이에 이전 선택 스냅샷으로 도구를 다시 설정하지 않는다. 예를 들어 Fill 초기화가 색상을 초기화하면서 이미 수락한 Solid를 이전 Gradient로 되돌려서는 안 되며, 해당 뷰에 없는 geometry는 유지한다.

QML에 남은 Canvas/Shape 그리기, 좌표·색상·너비 바인딩, 화면 크기에 따른 레이아웃, 포커스·스크롤·팝업 전환은 뷰의 책임이다. 이것을 없애기 위해 GUI 객체를 하위 순수 모델로 넘기지 않는다. ViewModel의 판단이 필요한 이벤트는 C++로 전달하고, 반환된 표시 명령으로 화면을 연다.

## 카탈로그 유지보수

생산 JavaScript 12개를 제거했다. 정의 데이터는 `resources/viewmodels/`의 JSON으로 포함한다. 그래픽 패널 381개와 기존 모든 필드·연산 기본값을 보존한다. `tools/generate_graphic_panels.py`는 편집기 매니페스트와 네이티브 JSON을 함께 생성한다. `--javascript`는 이전 구현 비교용 테스트 자료를 명시적으로 만들 때만 사용한다.

원본 Figma 수집 자료가 없는 체크아웃에서도 검토된 소스 매니페스트로 네이티브 자원을 검증할 수 있다.

```sh
python3 tools/generate_graphic_panels.py --from-manifest src/App/Views/Editor/GraphicPanels.json --check
```

이전 JS와 타임라인 상태 구현은 `tests/fixtures/legacy-viewmodels/`에 동결되어 있다. 앱 QML 자원에 포함하거나 새 기능을 이 자료에 구현하지 않는다. 데이터 카탈로그 변경은 독립 Figma/SDK 계약 테스트와 네이티브 기본값 테스트를 갱신해야 한다.

## 검증 방법

빌드는 기존 `build/`만 사용한다.

```sh
cmake --build build --target DreamscapesNativeViewModelTests DreamscapesViewModelBridgeTests DreamscapesViewModelAdapterTests DreamscapesReviewModelTests DreamscapesAdvancedParametersTests --parallel 4
ctest --test-dir build -R 'Dreamscapes\.(NativeViewModels|ViewModelBridge|ViewModelAdapters|NativeViewBoundary|ReviewModel|AdvancedParameters)$' --output-on-failure
```

- NativeViewModels: Qt 없이 값 경로·검증·타임라인·초안·선택·명령 계획·행 차이·실제 iiSDK 작업 풀을 검증한다.
- 표시 조회·재생·팔레트: 숫자 표현이 다른 선택값, 음수 범위, 원본 스냅샷 유지, 단조 시계의 지연·반복·종료·스냅, 잘못된 입력 거부, 단색 그레디언트를 검증한다. GUI 연결 검사는 URL·날짜 형식 보존, 실제 타이머 진행, 화면 중단·소유자 파괴와 문서 변경 없음도 확인한다.
- ViewModelBridge: 동결한 이전 구현과 전체 그래픽 카탈로그·기본값·중첩 경로·숫자 입력·타임라인 명령의 결과를 비교한다.
- ViewModelAdapters: 초기화 순서, Undo 초안 보존, 캔버스 생성 입력, 공유 소유권, 없는 런타임 거부 및 QML 네이티브 등록을 검증한다.
- 기존 GUI/생성/타임라인/그래픽/저장소 회귀 검사는 연결된 실제 화면 동작을 검증한다. 단위 테스트 성공을 앱 전체 또는 설치본의 성공으로 대체해서 보고하지 않는다.

생성 배치 취소 회귀는 중복·미확인 ID가 섞인 선택을 취소해도 다른 작업 공간의 대기 작업, 모델 선택 및 Generation History가 유지되는 것을 검증한다. 같은 선택을 다시 취소하거나 빈 선택을 전달해도 새 작업 변경 알림을 만들지 않는다.

소스 화면만 반복 검사할 때에는 `DreamscapesGuiSourceTests`를 빌드하고 필요한 QtTest 함수를 지정한다. 이 타깃은 앱 번들을 매번 재포장하지 않는다. 배포와 패키지 실행 검증에는 기존 `DreamscapesGuiTests` 및 정식 앱 빌드를 사용한다.

공유 스토리지 연결부는 설치 SDK가 `openForApplication`을 제공하면 앱 식별자로 연결하고, 이전 SDK에서는 기존 기본 연결을 유지한다. 사용자가 명시한 경로는 두 버전 모두 우선한다. 화면 투영이 이 연결을 임의로 시작하지 않는다.

네이티브 투영은 결과의 ID와 순서를 결정한다. URL·날짜 및 임의 메타데이터의 원래 GUI 래퍼는 연결부에서 원본 스냅샷으로 복원하여 전달한다. 생성 결과를 순수 모델로 왕복했다고 원본 참조 형식이 바뀌어서는 안 된다. 숨겨진 파일 화면의 오래된 응답은 버리되, 다시 표시할 때 마지막 입력의 투영은 재요청한다.

파일 목록도 같은 경계를 지킨다. 연결부는 현재 세대의 Alias 원본을 보관하고, 작업자가 변경하지 않은 필드는 원래 GUI 값으로 복원한다. 폴더 합성과 비디오·포스터 연결처럼 실제로 파생한 필드는 네이티브 계산 결과를 유지한다. 목록 재표시는 컨테이너 ID가 검증된 Alias만 대상으로 한다.

Home의 독립 이미지 다중 선택도 네이티브 키로 선별한 뒤 원본 항목을 반환한다. 새 결과 도착·전체 선택 때문에 원본 URL이나 생성 메타데이터의 형식이 바뀌지 않는다.

Generation History와 검색도 같은 방식으로 원본 행을 채택한다. 섹션 사이에 동일한 ID가 반복되어도 각 행의 임의 메타데이터를 혼합하지 않는다. 네이티브 결과의 순서·라벨·포스터 변환은 유지하고, 변환되지 않은 원본 URL·날짜 형식은 연결부에서 복원한다.

날짜 계산용 입력은 UTC ISO 8601로 정규화하여 요일·월 이름의 문자열 순서로 최신 파일을 잘못 정렬하지 않는다. 표시·전달용 QDateTime 원본은 위 연결부에서 유지한다. 네이티브 조회 메서드를 뷰 바인딩에서 호출할 때에는 해당 입력 속성의 변경 의존성을 명시한다. C++ 내부 조회가 QML의 JavaScript 의존성 추적을 자동으로 제공한다고 가정하지 않는다. 회귀 검사는 이전 JavaScript 함수 시그니처 대신 실제 C++ 타입·반환형을 사용하며, 거부된 편집의 Undo/Redo 깊이도 비교한다.

iiSDKCore Value의 유한수 계약을 지키면서, 타임라인 명령은 NaN/무한대 여부를 명시적인 검증 플래그로 전달한다. 잘못된 FPS를 null 또는 현재 FPS로 대체하여 수락해서는 안 된다. FPS 생략은 별도의 한 인자 메서드로 구분하며, 지원하지 않는 트랙 생성은 빈 ID를 반환한다. 비동기 목록을 검사하는 GUI 테스트는 교체될 수 있는 이전 delegate의 포인터를 재사용하지 않는다.

검증 로그는 `build/qml-native-refactor/`에 둔다. 전후 소스 스냅샷은 같은 폴더와 `build/qml-native-refactor/source-before.zip`에 있다. 응답 시간의 한 번 측정으로 전체 앱의 배속이나 FPS 개선을 주장하지 않는다. 빌드 산출물, GUI 검사, 기존 설치본 교체 및 실행 프로세스는 각각 별도 증거가 필요하다.


## 2026-10-26 추가 검증

추가 이전의 기록은 `build/native-view-completion-20261026/`에 있다. 소스 기준선과 이전 변경의 패치를 보존하고 순수 네이티브·연결부·선택·QML 경계·고급 파라미터의 CTest 6개 묶음이 모두 통과했다. 화면 연결 회귀는 macOS offscreen에서 27 passed / 0 failed이며 데스크톱과 모바일 크기의 레이아웃을 포함한다. 격리된 컨테이너로 정식 앱 번들을 실행하는 검사와 깊은 서명 검증도 통과했다. 순수 뷰모델 검사 실행 파일은 iiSDKCore 0.18.1과 표준 런타임만 링크하며 Qt를 링크하지 않는다.

전체 비디오 흐름 검사에서는 이미지 키프레임 가져오기 단계의 `database is locked`가 별도로 재현되었다. 실패 로그는 `gui-final.log`에 보존한다. 이 경로의 성공이나 실제 LTX 추론 성공을 위 화면·모델 검사 결과로 대신하지 않는다. 앱 설치본 교체나 실행 중인 사용자 프로세스의 재시작은 수행하지 않았다. 자세한 결과는 같은 폴더의 `verification-summary.json`에 정리한다.
