# 작업 패널의 외곽선

Dreamscapes의 작업 패널은 회색 1px 외곽선과 반경 0의 직각 모서리를 사용한다.
인접한 작업 영역의 경계를 명확히 보여 주기 위한 앱 공통 표현이다.
외곽선 색상은 LVRS의 `Theme.accentGrayMuted`이다. 현재 기본 테마 값은
`#5A5D63`이며 폭은 QML 좌표계의 1 논리 픽셀이다. 고해상도 화면에서도
패널과 같은 좌표계를 사용한다.

## 적용 범위

- Home 개선안과 공통 탐색 사이드바는 외곽선 적용에서 제외한다. 생성 입력·큐·파일 목록·선택 파일·최근 생성 결과는 투명 표면을 사용한다.
- 이미지·비디오: 생성 설정, 입력 캔버스, 결과 미리보기와 타임라인
- 생성 검토: 헤더, 큐, 결과 그리드, Inspector, 비교 화면, 선택 작업 바
- 에디터: 문서 컨트롤, 캔버스 작업 영역, 페이지 목록, 세로 도구 모음,
  도구 Inspector, 타임라인, 상세 보기 옵션과 도구 Sheet. 상단 보기 바와
  공통 탐색 사이드바는 제외한다.
- 파일 목록, 환경설정의 목록 패널, 퍼블리싱의 문서·캔버스·설정·리뷰 영역
- 모바일: 기존 레이아웃을 유지하는 작업 영역과 Sheet

반경 0은 패널 표면에 적용한다. 이미지 카드, 버튼, 입력란, 색상 스와치,
선택 표시와 타임라인 클립은 각 컨트롤의 기존 LVRS 표현을 사용한다.
툴팁·메뉴 및 운영체제가 제공하는 창과 파일 대화상자는 별도의 표면이다.

## 공유 경계

`PanelFrame`의 네 변은 `topEdge`, `rightEdge`, `bottomEdge`, `leftEdge`로
개별 지정할 수 있다. 기본값은 모두 true이다. 독립 패널은 기존 네 변의
외곽선을 유지하고, 맞닿은 에디터 패널은 공유 변을 한쪽에서만 그린다.
네 변이 모두 켜진 경우 기존 Rectangle border를 사용하고, 일부 변만 켜진
경우 정확히 한 논리 픽셀인 사각형으로 그린다. 레이아웃·입력 계약은 같다.

에디터의 외곽, 캔버스 열의 우측, 툴바의 우측, 타임라인의 상단이 각각
경계를 소유한다. Inspector와 캔버스는 이 선들로 둘러싸이므로 인접한
두 패널 안쪽에 별도의 선이 생기는 2px 문제를 만들지 않는다.
자세한 소유권과 최소형 타임라인은 [에디터 레이아웃](EditorCompactLayout.md)을 참조한다.
앱의 새 캔버스 대화상자에도 같은 외곽선을 적용한다. LVRS Modal을 사용하는
실패 설명·폴더 선택 대화상자는 공개 속성인 `frameCornerRadius`만 0으로
설정한다. 해당 SDK는 Modal 프레임의 외곽선 속성을 공개하지 않는다.

## 구현 계약

`src/App/Views/PanelFrame.qml`은 투명한 장식 전용 Rectangle이다.
입력을 받지 않으며 접근성 탐색에서도 제외된다. 패널의 크기와 위치를
따라갈 뿐 문서·파일·생성 상태를 변경하지 않는다. 자식 콘텐츠보다 위에서
그리므로 캔버스나 스크롤 콘텐츠가 외곽선을 덮지 않는다.

일반 Item 패널에서는 `readonly property Item panelFrame`에 프레임을 소유시키고
시각적 부모를 해당 패널로 지정한다. Layout이나 LVRS의 기본 콘텐츠 별칭에
프레임을 직접 삽입하지 않는다. 그렇지 않으면 장식이 새 행 또는 delegate로
취급되어 간격과 높이가 바뀔 수 있다.

스크롤하는 홈의 섹션은 Flickable의 `contentItem`에 프레임을 두고
`target`으로 해당 섹션을 지정한다. 프레임이 대상까지의 조상 좌표를
관찰하므로 리사이즈와 스크롤에 맞추어 이동한다. 고정된 스크롤 패널의
외곽선은 viewport 자체를 부모로 사용한다.

`PanelSheet.qml`은 LVRS Sheet의 공개 `background`와 `cornerRadius`만
사용하는 앱 어댑터이다. 헤더·안전 영역·스크롤·포커스 반환은 기존 Sheet가
관리한다. 배경 프레임은 콘텐츠 아래에 두어 불투명 표면이 컨트롤을 덮지
않도록 한다. SDK 자체의 기본값이나 전역 Theme 배율은 변경하지 않는다.

새 작업 패널을 추가할 때에는 공통 프레임을 사용하고 기존 배경의 반경을
0으로 맞춘다. 프레임이 이미 있는 상위 패널의 단순 파라미터 행에는 중복
외곽선을 추가하지 않는다. 패널 간 간격·크기·컨트롤 상태도 유지한다.

## 검증

전용 테스트는 `tests/tst_panelframes.cpp`와 CTest의 `Dreamscapes.PanelFrames`이다.
다음 계약을 실제 QML 장면에서 확인한다.

1. 모서리 픽셀이 회색이며 외곽선 다음 픽셀부터 원래 배경이 보인다.
2. 장식이 마우스 입력을 통과시키고 Layout의 행 높이와 간격을 바꾸지 않는다.
3. Home 개선안의 표면과 사이드바는 프레임이 없으며, 그 외 기존 작업 패널은 각 화면의 계약을 유지한다.
4. 에디터 도구 18개를 전환해도 Inspector의 프레임을 유지한다.
5. 창 크기를 바꾸어도 외곽선이 대상의 위치와 크기를 따른다.
6. Sheet의 표면이 직각이고 내부 콘텐츠가 유지된다.

테스트는 `build/` 아래에 격리된 Society 컨테이너와 설정을 만들며 사용자
저장소나 모델 추론을 사용하지 않는다. 실제 앱 QML을 그린 검증 이미지는
`build/panel-frames/`에 저장한다. 빈 컨테이너 화면이므로 사용자 작업물이
포함되지 않는다.

기존 에디터 회귀 검사의 투명한 둥근 모서리 조건도 회색 직각 모서리의
실제 픽셀 검사로 갱신한다. 홈의 생성 이력 회귀 검사는 원본 25개 파일의
이름과 바이트가 유지되는지 검사한다. iiFileProvider `FileCatalog`가
비동기로 만드는 `<원본>.iisacc.json` 동반 파일은 해당 SDK의 기존 계약이므로
원본 파일 수에 포함하지 않는다. 그 외 새 파일·누락·원본 바이트 변경은
실패로 취급한다. 이 변경으로 카탈로그 작성 시점에 따라 단순 전체 파일 수
검사가 실패하던 문제를 제거하면서 원본 보존 검사를 강화한다.

```sh
cmake --build build --target DreamscapesPanelFrameTests
ctest --test-dir build -R '^Dreamscapes.PanelFrames$' --output-on-failure
cmake --build build --target Dreamscapes
ctest --test-dir build -R '^Dreamscapes.PackagedApplication$' --output-on-failure
```
