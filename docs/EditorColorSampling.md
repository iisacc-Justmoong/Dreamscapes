# 캔버스의 한 점 색상 읽기

`EditorColorSampler`는 화면과 파일 명령에서 분리한 C++ 읽기 작업 소유자이다. 작업 스레드에는 불변 `EditorFrameSnapshot`, 클릭한 세계 좌표, 작성된 아트보드·레이어 가시성, C++23 중지 토큰만 전달한다. 살아 있는 캔버스, QML 객체, 파일 바인딩은 전달하지 않는다.

SDK `iiSharedCanvas 0.31.4`의 `renderArtboardRegion` 또는 `renderFrameRegion`으로 원본 프레임의 1×1 영역을 읽는다. 아트보드 배경, 소유 레이어, 음수 원점, 프레임, 투명도와 기존 합성 규칙을 유지한다. 초점 표시 때문에 숨겨진 가시성은 작업 스레드의 문서 사본에서 복원한다. 출력은 한 픽셀이지만 필터의 원본 준비 비용까지 상수 시간이라는 뜻은 아니다.

## 요청과 표시의 계약

- `sampleLayerColor`의 성공은 요청 수락이다. `layerColorSample.pending`이 참인 동안 마지막 성공 색상과 `sequence`는 유지되며 완료 후 갱신한다. `error`, `frame`, `artboard`, `position`으로 실패와 실제 표본 출처를 구분한다. 속성 조회는 렌더링이나 파일 접근을 하지 않는다.
- 처리 중인 작업 하나와 최신 대기 작업 하나만 보유한다. 새 클릭과 취소는 이전 결과의 적용을 금지한다. 소유자 종료는 작업 스레드를 기다리지 않는다. 완료 상태를 먼저 정리한 뒤 관찰자에게 알린다.
- 일회성 색상 표본은 클릭 당시 프레임·아트보드를 유지한다. 이후 확대, 이동, 프레임·아트보드 탐색으로 그 표본의 출처를 바꾸지 않는다. 문서 교체, 실제 리비전 변경, 스트로크 시작, 도구 변경, 명시적 취소·Escape는 이전 읽기를 폐기한다.
- 화이트 밸런스 표본은 실제 편집 명령이므로 프레임·아트보드·선택 레이어·색상 설정 변경에도 폐기한다. 온도와 틴트는 한 처리와 한 지속적 편집으로 반영한다. 이 최종 픽셀 처리와 저장 자체는 아직 GUI 호출 경로에 있으므로 별도의 최적화 대상이다.
- 유효하지 않은 좌표, NaN, 무한대는 캡처 전에 거절한다. 투명 픽셀도 정상 결과이다. 읽기 대기·실패·취소는 문서 리비전, 저장 파일, Alias 버전을 변경하지 않는다.
- 선택·처리 중에는 십자 커서를 쓰고 브러시 크기 윤곽을 숨긴다. 패널은 `pending`을 기다리며 완료 전에 이전 색상을 새로운 결과로 사용하지 않는다.

## 검증

`Dreamscapes.ColorSampler`는 기본 합성, 불변 입력, 작업 중 UI 이벤트 처리, 최신 대기 요청, 취소, 비차단 소멸, 재진입 관찰자, 작업 예외, 대형 아트보드의 한 픽셀 출력을 검사한다. `Dreamscapes.CanvasColorSampling`은 실제 캔버스의 파일 무변경, 탐색과 표본 출처, 무효화, 좌표 검증, 화이트 밸런스의 단일 지속적 편집과 원본 재열기, 커서를 검사한다. `Dreamscapes.EditorTools`에는 2048×2048·32레이어 조건의 호출 반환 지연 회귀 검사가 있다. 테스트는 별도 데이터와 offscreen 화면을 사용한다.

불변 렌더 스냅샷의 최초 생성 비용은 기존 SDK 캐시에 의존한다. 이 변경을 전체 앱의 응답 시간, 모든 편집 명령의 비동기화 또는 설치된 앱의 실행 검증으로 해석하면 안 된다.
