# Background tool panel

The native desktop dock and mobile sheet share `EditorBackgroundPanel.qml`,
matching Dreamscapes Figma `777:82068`. The four icon segments select Color,
Remove, Mask and Replace. Every state has its own presenter; none falls back to
the legacy generic field list. The panel keeps each state's draft when changing
segments. The dock scrolls all sections at narrow or short window sizes.

## Design and controls

The reference panel is 432 px wide, with a 1 px border, 16 px padding, 16 px
corners, 12 px navigation spacing and 16 px between body sections. Controls use
the installed LVRS framework. Background navigation uses the existing local
Figma SVGs at 18 px; replacement actions use the corresponding LVRS icon assets.
The editable color fields are generated by iiColorManager rather than screenshots.

The action buttons in Figma `1023:70875` use the LVRS Default role: Apply color,
Remove background, New mask, Apply mask, Generate replacement and Apply
replacement. Apply removal also retains Default when its preview becomes ready;
readiness changes only `enabled`. Hover and press use that role's existing LVRS
surfaces. The editable Figma instances use `Kind=default`, with hover/press
prototype destinations in the same Kind. Combo-box indicators and selection
controls retain their existing component roles.

The alpha rail displays transparency against the panel surface, and the hue rail
follows the reference's downward hue order. Picker markers remain inside the
field at channel limits. Other shared pickers retain their checkerboard preview.

| State and Figma frame | Native controls |
| --- | --- |
| Color `777:82599` | Nine-mode combo above the picker; hue/brightness/wheel or channel ramps; Hex/Alpha and simultaneous RGB/HSB/Lab/CMYK inputs; opacity and bleed preference; swatches, recent colors, editable multi-stop gradient, geometry/interpolation/angle, six presets, Apply and Save preset |
| Remove `777:82729` | Input/model/foreground/quality choices; run/cancel; real before/after/split preview and mask overlay; threshold, edge radius, smoothing, feather, shift, detail/color refinement; brush/mask handoff; editable-mask output and original preservation |
| Mask `777:82857` | Icon toolbars for selection and mask actions, single-row numeric controls, dynamic named mask collection, compact pressure/new-mask/overlay switches and apply/reset; see [mask behavior](EditorBackgroundMask.md) |
| Replace `777:82980` | Generative/image/file source icons, prompt/model/count/strength, file drops and chooser/clipboard/recent files, fit/scale/angle/offset, blend/opacity/subject matching, preservation and output action icons |

Color edits are drafts until Apply. Solid and sorted multi-stop linear/radial
fills produce a real background layer in one undoable transaction. The fill
uses color alpha and opacity; Perceptual interpolates in Lab through
iiColorManager. The current finite canvas API has no separate print bleed
region, so its bleed preference currently has the same extent as the canvas.
Added swatches and saved gradients are available from the same panel draft.
Color/alpha synchronization never publishes a user edit: entering alpha first
retains that value, and returning from another segment preserves the chosen
gradient and transparency without a binding loop.

Image/file replacement accepts local raster images and IISC canvases through
the existing working-canvas importer. Clipboard images remain in memory until
applied. Fit/Fill/Stretch, scale, rotation and offsets produce native editable
layer transforms; opacity and blending remain layer properties.

Artboard-owned fills and replacements use local transforms, so an artboard's
world offset is applied exactly once. Loose/infinite canvas layers retain their
canvas origin. Existing direct generated-background placement keeps its legacy
replacement behavior; the new panel follows its explicit Output selection.
Lighting match uses the selected artwork's average color and the Subject match strength.
Preserve subject inserts the replacement below existing artwork. Generated
replacements use the existing queue and result selection, retaining the chosen
model, variation count, strength, seed and placement settings.

## Availability and verification boundaries

The removal path consumes actual semantic segmentation regions in the canvas.
It does not install or infer an ML model. A canvas without the requested region
returns an actionable error and keeps Apply disabled. Preview does not commit
document changes. Applying a current preview adds a native editable mask;
preserving the source creates a derived layer and hides the original. Changed
documents or changed target layers require a new preview. Invalid numeric
parameters cannot commit a document mutation.

`DreamscapesMaskPanelTests` exercises native edits/history, input validation,
semantic preview and mask output, replacement placement, and all four LVRS
states at 280/402/432 px. Native captures are written beneath
`build/background-panel-verification`. Packaged application startup and signing
are separate checks from source-panel rendering and from an already running
installed application.

The four-state view regression also checks all seven action roles and the
disabled/ready transition of Apply removal without changing its tone.
