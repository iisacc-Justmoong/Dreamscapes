# 생성 프로세스의 소유권과 UI 전달

외부 추론 워커를 사용하는 경로는 `GenerationProcess`를 거쳐 iiSDKCore 0.18.1의 `ii::process::Process`와 `ii::runtime::EventLoop`를 사용한다. GUI 객체는 값으로 전달된 상태와 순서가 보존된 출력만 받는다. 앱의 나머지 실행 경로 전체가 Qt에서 독립했다는 의미는 아니다.

## 작업자 경계

프로세스 시작, 비동기 파이프 읽기·부분 쓰기, 실행 상태 확인, 취소 및 소유한 하위 프로세스 회수는 전용 네이티브 작업자에서 수행한다. 프로그램과 인자는 개별 문자열로 전달하며 셸을 통하지 않는다. 환경 변경은 Core의 `EnvironmentPatch`로 적용한다. 플랫폼의 프로세스 지원 여부는 SDK의 capability 계약을 따른다.

작업자는 공용 iiSDKCore `Runtime`에 제출하여 재사용한다. 앱 종료 신호에서는 접수를 닫고 모든 소유한 세션에 중단 의도를 전달한 뒤 Runtime을 회수한다. 개별 화면 소멸은 작업자를 기다리지 않는다. 앱 종료 시의 회수는 화면을 제거하는 경로와 별도의 수명 경계이다.

작업자에서 GUI로 보내는 출력 대기량은 1 MiB로 제한한다. 가득 차면 읽기 관심을 중단하고 GUI가 소비한 뒤 다시 등록한다. 양쪽의 한 번 처리량은 64 KiB이며, 출력 이벤트 뒤에 종료 이벤트를 넣어 마지막 결과나 오류를 빠뜨리지 않는다. 기존 생성 프로토콜, 작업 순서, 캐시 재사용 및 결과 공개 경로는 유지한다.

작업별 입출력·프리뷰 디렉터리와 워커 실행 디렉터리는 공유 수명으로 붙인다. 유효한 결과를 받은 뒤 작업 입력 수명을 해제하며, 취소 또는 화면 제거 시에는 Core가 프로세스를 회수할 때까지 유지한다. 완료 상태는 기존 비동기 파일 정리가 끝난 뒤에 공개한다. 화면 소멸자는 프로세스 종료를 기다리지 않으며 작업자의 수명은 UI 객체에 의존하지 않는다.

## 취소와 진행 감시

Core의 취소는 소유한 프로세스 트리를 종료하고 직접 자식을 회수한다. 기존 GUI의 PID 기반 신호 전송과 최대 1초 종료 대기를 제거했다. 이 경로의 생성기는 비공개 임시 파일에만 쓰며 최종 파일 공개는 별도 검증 작업이 담당한다. 임의의 다른 프로세스는 취소 대상에 포함하지 않는다.

진행 감시 타이머가 만료되면 GUI에서 기다리는 대신 네이티브 출력 확인을 요청한다. 먼저 도착한 출력이 전달된 다음 확인 이벤트를 처리한다. 진행이 갱신되었거나 작업이 바뀌었거나 공개·취소가 시작되었다면 이전 타이머의 판단을 버린다. 단순 heartbeat는 진행으로 간주하지 않는다.

워커가 종료된 뒤에도 확인 이벤트는 같은 출력 FIFO의 끝에 넣는다. 별도의 GUI 콜백으로 전달하면 64 KiB씩 나누어 전달하는 출력의 다음 차례를 추월할 수 있기 때문이다. 작업자가 아직 종료 중이어서 명령을 받지 못한 경우에는 GUI를 막지 않고 재요청한다. `terminalProbeFollowsAllBufferedOutput` 검사는 네이티브 종료까지 GUI 전달을 보류한 뒤 이 순서를 검사한다.

## 검증 범위

`Dreamscapes.GenerationProcess`는 문자열·환경·작업 디렉터리, 바이너리 입력과 반복 요청의 PID 재사용, 다량 출력 중 GUI 이벤트 처리, 비정상 종료의 마지막 출력, 즉시 취소·실행 실패, 소유한 하위 프로세스 회수, 관찰자에 의한 UI 삭제, 실제 컨트롤러 종료와 임시 파일 회수를 검사한다. 기존 `Dreamscapes.Generation` 및 `LocalSociety` 검사는 바꾸지 않고 함께 수행한다.

닫기 시간 측정은 SIGTERM을 무시하는 격리된 프로세스를 대상으로 소멸자 시간과 이후 회수 시간을 분리한다. 이 결과는 전체 앱 종료 시간, 실제 모델 추론 속도 또는 화면 FPS를 뜻하지 않는다. 설치본 교체와 실행 중 앱 재시작은 별도 배포 증거가 있어야 확인된 것으로 취급한다.
